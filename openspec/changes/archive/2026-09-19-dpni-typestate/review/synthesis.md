## 2. Verdict — core promise: **YES**, with two documented soft spots

An invalid dpni create configuration is unrepresentable where claimed and typed-refused where recorded. Evidence (Pass 2 compile-vs-runtime table, all "as advertised = yes"):

| Invalid shape | Mechanism | Tier |
|---|---|---|
| Dead option / num_rx_tcs | no `DpniCfg` field; `DeadOptionRefusal` is the parity answer, not the guard | compile-time |
| Unnamed MC flag / arbitrary raw bit | no variant; additive-only `OptionMask` | compile-time |
| Create-time MAC; post-create cfg mutation | no field; no `&mut` path, `compile_fail` doctest `:594-600` | compile-time |
| Third profile / per-interface override / operator option token | two-variant `Profile`, total `derive_profile`, no parameter to pass | compile-time (D3) |
| Out-of-envelope numeric | `T::new → Result`; value type has no out-of-envelope inhabitant | runtime boundary, honestly documented (`:82-83`) |
| Unpriced dataplane; derived T/cpus>32 | typed refusals (`Unpriced`, `QueueEnvelopeExceeded`) | runtime, as guu.4a recorded |

Soft spots, neither falsifying the recorded wording: PASS2-F6 — the pub witness constructors admit a silent off-envelope degrade with no refusal on the hand-built-plan face; the claim survives because the recorded scope is the compile path ("undefined on refused intents"), but the precondition is undocumented. PASS3-F5 — tasks.md's "unconstructible" for empty `TenantName` is over-strong; the shipped closure is sentinel-mint-by-construct plus boundary convention. Both land as wording amends (rows 10-11), one optional hardening each.

## §5 Rule-amendment nominations

1. **Offline pre-check as a standing board-suite gate — ACCEPT, reshaped.** The 6.4 executor gap shipped through five task groups and only the 7.2 offline pre-check caught it; sittings are the scarce resource. The specific class is now mechanized in code (the exhaustive `reify_guard` refuses any compiled family without an executor), and ADR-0023/#15 answers orchestration ordering — so the rule is narrower than the candidate: amend the board-suite protocol so every sitting's pre-run record commit includes a named offline pre-check step (render the suite + run its intents against the fake backend end to end) and a kill-the-sitting rule on any typed refusal. Cheap, offline, and exactly what caught this defect.
2. **Re-seal task text when a named design decision is overturned — REJECT the re-seal; adopt annotate-at-bank instead.** tasks.md is an execution record; design.md D7 carries the correction and the brief rightly carves tasks.md:88 out as history. Rewriting sealed task text contradicts the amend-until-sealed convention for near-zero reader benefit. Reshaped rule: the close-out doc-bank task (the 8.1-style step) includes a sweep for design-decision names inside sealed task text and adds a one-line bracketed supersession note ("[superseded: D7 settled bpftrace]") as a forward edit — annotate, never rewrite. This epic shows the cost of doing nothing is one misleading parenthetical; the annotation costs one line.

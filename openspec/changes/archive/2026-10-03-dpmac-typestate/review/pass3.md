# PASS 3 report: dpmac-typestate (architecture and code quality)

## Mandate verdicts

**(a) Sans-io discipline — holds, one shell-side leak.** Every judgment is home in `families/dpmac.rs`: `judge_arbitration`, `judge_mac_relation`, `carrier_source`, `CarrierReading::from` are pure and core-side; the shim's `classify_dpmac_counters` (restool.rs:321) is the D4-protected southbound vocabulary check producing the typed `CounterReadout`; the deviating row count is a typed `VersionSignal` (restool.rs:330); the dead spawn is `Error::Backend` via `run_verb`'s `code: None` branch (restool.rs:505-511), proven by `observe_dpmac_dead_spawn_is_a_typed_failure_with_no_state` and the exactly-one-spawn test (shim.rs:517-530). The hal `carrier_of` (sysfs.rs:141-160) is policy-free: resolution rule in (netdev lookup), no retry/tolerance; `None` stays untyped and the caller judges `NoObservable`. The one leak is small and in tools (F3).

**(b) Display-only end-to-end — holds structurally.** Workspace-wide grep: `observe_dpmac`, `KernelControl::carrier`, `judge_arbitration`, `judge_mac_relation`, `CounterReadout`, `CarrierReading` have ZERO consumers in `plan/`, `reconcile`, or `engine` — the only production consumers are `status.rs::port_details` (main.rs:163-166, `Status --detail` only, after `StatusReport::compute`, exit code pinned to `report.has_diverged()` at main.rs:177) and `render.rs`. No carrier check before actuation, no counter gating a plan step. Pass 1's open question 2 (MAC relation / arbitration side doors): closed — MacRelation and Arbitration are computed only inside `port_details` and never escape it; the reconciler's MAC drift path (reconcile.rs:144-158) is the pre-existing dpni-typestate assert/actuate comparison on `dpni.mac`, not the port-detail judgment. (Whether that path carries D5's Pending exclusion — `dpni.mac == Some(ZERO)` under `MacMode::Assert` looks like it would report an assert mismatch — is Pass 2 scope, flagged in open questions.) The severed-witness is indeed the one typed demand the planner makes.

**(c) Reuse-before-write — one real duplication cluster (F2), the rest clean.** Shim fixtures follow the existing `include_str!` idiom; both new fixtures used; `OneShot` runner is justified (integration tests can't reach the lib's `#[cfg(test)]` `ScriptedRunner`). fake.rs additions (`with_carrier`/`set_carrier`/`set_counters`, carriers/counters maps) follow the fake's existing `with_*` builder + RefCell re-script idiom exactly. The carrier read reuses `netdev_of` and shares the driver-link/eth-unbind path idiom (`devices_root/<container>/<device>/...`, NotFound⇒None). The miss: the epic added a THIRD `dpmac info` parser instead of extending the existing raw surface (F2).

**(d) Seam quality for #8/#10/#12 — adequate.** `observe_dpmac` is one added `McControl` method (contract/mc.rs:63), per-family like the house idiom (dpbp_create…), so dpseci gets its own additive verb, no shared-P4-abstraction assumption to unwind. `RequestsDownChannel::Unreadable` (families/dpmac.rs:177-181) is payload-free; #10 makes it readable by adding a variant — additive. `COUNTERS_1040_EXT` + `FirmwareVersion::Mc1040` are named-unread in the api; `VersionSignal` already types the deviation. The one seam weakness: `CounterReadout::Vocabulary` carries neither the firmware version nor the verbatim row names (shim drops them at restool.rs:328), which both causes F1 today and forces the eventual 10.40 type change — fixing F1 is the additive #10 prep.

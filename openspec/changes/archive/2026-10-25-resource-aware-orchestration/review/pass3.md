Verdict up front: the sans-io seam is clean (all judgment in `dpaa2-api`, engine composes, render displays), the dispatch TABLE is the single door with no bypass or leftover 6.4 list, the V-ADMIT-1 suite meets the ADR-0003 protocol point for point, and the D10/#12 frame stands for dpdmux. Four findings, all carries-cost class; the dominant one is the confirmed and widened carry 2.

## Findings

**PASS3-F1 (carry 2 confirmed and costed: three snapshots inside one admission judgment)**
- file:line: `<repo-root>/crates/dpaa2-tools/src/engine.rs:1294` (plan_pools → `read_inventory` at :1235 + trio/dpio `observe_pool`, snapshot A), `:1295` (`read_inventory` again, snapshot B), `:1330` (`plan_switches` → `observe_pool(None, Dpsw)` at :911, snapshot C). Doc overclaim at `:1268` ("one read serves both").
- Category: duplicate (doc-drift at :1268). Superseded-by: n/a. Severity: carries-cost; misleads-a-reader for :1268.
- Costing (the Pass 1 open question 2): the POOL judgment is internally consistent — face free counts and pending creates both derive from snapshot A's drift. The FDB judgment is NOT: `face.fdb.draw` counts dpsw labels from snapshot B (:1306-1313) while `fdb_pending` counts Create/Recreate verdicts from snapshot C (:1330-1338). A dpsw destroyed between B and C is double-charged (still in B's observed draw AND now a pending create in C) → spurious refusal on a board that actually fits; a dpsw created between B and C overstates free → spurious admit that converts the planning-time refusal into the mid-run firmware errno the gate exists to preempt. The ensure-path comment (main.rs:297-300) declares admission advisory under D7, which caps severity — but D7's tolerance was written for the environment adversary, not a self-inflicted intra-judgment split; on a quiescent board the two views should be one view. Secondary cost: each read is a restool subprocess exec, so one `plan_admission` is ~7 execs where ~4 suffice.
- Disposition: fold — `plan_admission` takes (or returns) the single snapshot set: pass the drift's inventory down (have `plan_pools` return it or accept `&Inventory`) and accept the `plan_switches` work; amend the `:1268` doc to the truth. Readability cost: one extra parameter or a slightly wider `Admission` carrier — low.
- Verification: `grep -n "read_inventory()" crates/dpaa2-tools/src/engine.rs` shows one call reachable from `plan_admission`; `grep -n "plan_switches" crates/dpaa2-tools/src/engine.rs` shows no call inside `plan_admission`.

## Confirmations (checked, no finding)

- **Sans-io (mandate a)**: `admission.rs`/`capacity.rs`/`dispatch.rs` are pure data + functions, no io imports; `plan_admission` composes observation → face → pending → `from_pending` → `admit` with zero judgment of its own beyond the pending assembly (which IS the D8 composition, correctly engine-side since it reads pass-specific convergence verdicts); the ensure gate sits exactly `reify_guard` (main.rs:293) → admission (main.rs:301) → `converge_pools` Grow (main.rs:328) with no second decision layer — `converge_pools`' shrink-refusal and class gates are pre-existing, different judgments, and its own `plan_pools` re-read is D7 dispatch-time re-observation by design. Render is display composition only; `refused:` prefix matches the `render_drift_refusal`/`render_refusals` idiom; refusal text is data-only operator terms, no law IDs.
- **Single door (mandate b)**: no duplicate family→pass list anywhere — `reify_guard` (engine.rs:651-662) reacts to `disposition()`, the 6.4 interim list is absorbed, not duplicated; the `Attributes::*` matches in engine.rs (272, 715, 1056, 1882) are pass-scoped filters and render.rs:1200-1229 is display; `GrossDraw::from_pending` is the only production constructor (the literal at render.rs:1280 is a `#[cfg(test)]` display fixture; `GrossDraw`'s pub fields are the repo's data-only-face idiom) and it routes through `TABLE`'s `DrawKind` (admission.rs:73-80).
- **Suite protocol (mandate c)**: V-ADMIT-1.sh carries all ADR-0003 elements — repo-root cd with pre-cd SELF resolution (:40-42), total-deny self-check (:47-50), dpaa2ctl provenance incl. sha256 (:67), reference-pair assertion MC 10.39.0 / kernel 6.6.52 (:83-86), kmsg window with EXIT trap (:72-79), PASS/FAIL face log counted at close with nonzero on any FAIL (:92-158). The dpcon-only greps are **correct, not fragile**: the dpbp bonus refusal adds lines that `grep -q` ignores in both legs, and asserting dpbp would make the suite boot-fragile (dpbp tightness is boot-dependent free-count luck; the dpcon +200 is decisive on any boot per the operand header and V-DPRC-10). The offline pin compiles the exact committed operand through the same `complete_kernel` + `compile` pipeline and asserts the UnknownCeiling(dpcon) warning, the dpcon Pool refusal, zero dispatch, and the ensure voice — the dpcon-not-dpbp reasoning is documented identically in the test header, the script header, and the operand, consistent with the recorded board outcome.
- **Reuse (mandate d)**: `render_admission`/`render_admission_refusal` follow the established `render_*(carrier) -> String` seam; `Admission` mirrors the other `plan_*` seam carriers; `AdmissionRefusal` is kept a sibling of `Refusal` with the reason recorded (admission.rs:36-37). The engine tests exercise both the refusal-before-any-verb and the converged-fixpoint-re-admits scenarios against FakeBackend audit.

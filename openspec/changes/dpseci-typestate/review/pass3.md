# PASS 3: dpseci-typestate — Architecture, the unsafe debut, and code quality

HEAD unchanged at ae23721; grounding stands.

## Mandate verdicts

**(a) The fence is structural — PASS, stronger than mandated.** `DpseciRead` (crates/dpaa2-hal/src/portal.rs:92) is a closed five-variant sum; cmdids are private consts derived only by the `encode` match (portal.rs:234-240) — no path accepts an arbitrary command id, and `McPortal::execute` takes only the sum. `Token`'s field is private, mintable only from an `Open` response. There are **no transmutes at all**: the frame is hand-serialized into `[u8; 64]`, so the sole unsafe is the one `libc::ioctl` call (portal.rs:337-351) under a scoped `#[allow(unsafe_code)]` with crate-level `unsafe_code = "deny"` (Cargo.toml:17-21) — a smaller unsafe surface than the brief's recorded "ioctl + transmutes" shape. Decode cannot panic or hit UB: all offsets are constants < 64 into a fixed array, decode is total per variant, and an unknown status rides back verbatim as `McStatus::Unknown` (portal.rs:213). Every constant cites its pinned source (`fsl_mc_cmd.h`, `fsl_dpseci_cmd.h`, `fsl_mc_ioctl.h:47`, mc-ioctl-policy rows 24/38/41-43) and the tests pin the V1 macro, the whitelist mask rule, the ioctl request code (0xc040_52e0), and golden frames for all five commands plus all three outcomes. The three outcomes are honestly disjoint: `Outcome` has exactly two variants (Response/Status) and the transport refusal is the `io::Result` Err, never a value. As the precedent #10 inherits, this is a good one.

**(b) Sans-io discipline — PASS.** portal.rs contains zero retry/tolerance/judgment; all mapping lives in dpaa2-mc: `classify_portal_io` (NotFound/PermissionDenied → typed `Unobservable`, else Backend), `portal_mc_refusal`, and the Open→GetAttr→GetApiVersion→Close session in `read_dpseci_over_portal` (restool.rs:364-432). The lbk.14 routing law sits exactly where claimed: `root_portal()` is a private inherent method on `RestoolMc` (restool.rs:828-833) with the `DprcId::ROOT` fallback, pinned by the sentinel-root test at restool.rs:2762-2783 (`dprc.64998`, asserts root node tried AND child node not tried). It touches no trait seam; `McControl::observe_dpseci`'s signature is byte-for-byte (the impl ignores `_container`, restool.rs:1053). Census/signature law lives entirely in dpaa2-api core (`plan/dpseci.rs`: `Sig`, `sig_of`, `observed_sig_of`, `sig_census`, `census_delta`); dpaa2-mc's `judge_dpseci` (populate.rs:140-167) only plumbs custody filtering and calls the core functions. Options wire-bit encode/decode (`dpseci_opt_bit`, `decode_dpseci_options`) sits in restool.rs — correct per ADR-0018 (adapter policy maps), and `dpseci_options_mask` folds both named flags AND raw escapes (restool.rs:244-253), so the escape path is not dropped on the wire. Tools stay display composition: render.rs:568-635 formats only; no judgment. dpaa2-tools has no dpaa2-hal dependency (Cargo.toml check), so the portal cannot be reached around dpaa2-mc.

**(c) Observation stays display-only — PASS.** No side doors found: `api_major/api_minor` flow only to render/fake/tests (workspace-wide grep); the census consumes exactly `ObservedSig` (num_queues + options) via `observed_sig_of`; priorities and API version never enter `Sig`. The detail gathering in main.rs:164-176 runs only under `--detail`, after reconcile, with the exit code explicitly port-driven. `RawDpseciInfo` carries no options field by type (parse.rs:390-405), so the wrong observable cannot typecheck. An unobservable face dispatches nothing and counts as no-pending-work (populate.rs:93-101, 298-300) — absence of evidence never gates or churns.

**(d) Reuse and #10 seam quality — PASS with notes.** The pool trio census (`PoolCensus`: count-level with custody splits, pool_lifecycle.rs:236-258) and the signature multiset (`BTreeMap<Sig, i64>`) are genuinely different shapes — the re-derivation is justified, not a missed fold. The fixture pattern (include_str! `dpseci_info.txt` with provenance comment, shim.rs:41-46) and fake.rs idioms (scripted detail map, unknown-object error arm mirroring `observe_dpmac`, builder `with_*`, `push_pool_object` reuse, audit push) follow the existing conventions exactly. For #10: the frame codec, header offsets, `McStatus`, `Token`, `Outcome`, and the ioctl confinement are all command-agnostic and transfer untouched; the only #10 rework is generalizing `execute`'s parameter from the concrete `DpseciRead` to whatever command vocabulary #10 defines — contained inside hal and deliberately so (ADR-0021: #10 owns vocabulary growth). The shim exposes the full GET_ATTR witness (`DpseciObservation` carries portal queue counts) and projects the contract subset at the trait boundary — a good full-witness-at-shim / projection-at-seam precedent. Nothing encodes a read-slice assumption #10 must rewrite.

## Ruling on Pass 1 open question 2 (the `container` parameter)

**Keep the parameter; amend docs only** (PASS1-F7/F8 dispositions stand). Three reasons: (1) removing it breaks the byte-for-byte contract claim of the lbk.14 close and churns FakeBackend, populate.rs:149, status.rs:184, and tests for zero behavior; (2) the trait stays symmetric with `observe_pool(Some(child), …)` — the census law is per-container (D9), and the seam must keep that scope expressible even when one backend routes reads globally; (3) it IS the #10 seam: an ioctl backend's container-scoped observation (the `dprc show` equivalent, or a delegated non-root portal) consumes it naturally, while root-routing stays restool-shim policy exactly where it belongs. The fix is the doc amendment only.

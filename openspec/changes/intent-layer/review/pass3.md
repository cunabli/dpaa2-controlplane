# Pass 3 — dpaa2-api (`intent-layer`, 648f804..4272019)

## Answer to Pass 2's open question 1 (PASS2-F3 confirmation)

**Confirmed, with a correction to the framing: the divergence is NOT model-vs-Rust — model and Rust agree, and both are tenant-position-dependent.** `derive()` (`/workspace/dev/clearfog-cx-lx2/src/dpaa2-controlplane/crates/dpaa2-api/src/derive.rs:1095-1116`) folds `effective_tenants` — a verbatim `intent.tenants.clone()` in declaration order (`:566-572`) — into the emission `order` Vec with no sort, exactly mirroring the model's `fullOrder`. Ports, links and fabrics ARE name-sorted where consumed (`terminated_ports :149`, `origin_list :258,:275`, `hw_owned_fabrics :200`); tenants never are. The `objects`/`edges`/`provenance` fields are BTree collections and thus order-free; **only `CompiledPlan.order` carries the tenant-position dependence** — and the position-independence the docs claim is actually supplied one crate upstream, by `dpaa2-config`'s `BTreeMap<TenantName, RawTenant>` (`crates/dpaa2-config/src/schema.rs:142`). The Rust I10 property test says so honestly (`crates/dpaa2-api/tests/compile_props.rs:948-949`: "fabrics/tenants are name-keyed tables **the parser canonicalises**") — while `intent.rs` claims the opposite ("the derivation sorts them by name … no longer consumes their order"). So PASS2-F3's fix must land on **both** sides in lockstep: `sortByRank` tenants in the model's `fullOrder` AND a one-line name-sort in `effective_tenants` (or both claims scoped to the parse boundary). A library user building `Intent` directly (the design-D11 surface) today gets an order-dependent emission list from two intents the docs call equal.

## Structure verdict (dpaa2-api)

**keep-flat.** 15 modules, one >1k-line file pair (`refuse.rs` 1,860 — but ~950 of that is the one-test-per-variant suite; `derive.rs` 1,129). The three strata a grouping would draw — vocabulary (`types`/`family`/`intent`/`inventory`), compile pipeline (`derive`→`compiled`→`refuse`), actuation+identity (`model`/`plan`/`reconcile`/`port`/`fake`/`matcher`) — are already communicated by `lib.rs`'s re-export blocks and each module's first paragraph, and every module header names its qnt twin, which a `src/compile/` nesting would only push one path segment away from the flat `models/intent/*.qnt` namespace it mirrors. A move would touch ~7 files, force `pub(crate)`→`pub(super)` churn on the `derive`⇄`refuse` seam, and communicate nothing the current layout doesn't. The one growth valve to pull first if `refuse.rs` keeps growing: move its 24-variant `compile_tests` module to `tests/` (0 API change, −950 lines). Files-moved count: 0 now.
